---
title: Depth, power, and modes
description: Tune thoroughness, model power, tournaments, and autonomy.
---

Two dials and two modes tune a run. You set them as flags on
[run](/docs/cli/run); the flow rejects anything it does not support, before
the run starts.

## Depth

Depth is the process dial: how much thoroughness and care a flow spends.

```bash
circuit run build --goal "..." --depth high
```

| Value | Description |
| --- | --- |
| `low` | Less care. For Fix, also drops the independent review stage. |
| `medium` | The default. |
| `high` | More care. Checkpoints pause for you instead of auto-resolving. |

Build, Explore, and Fix support all three values. Prototype supports `medium`
and `high`. Review and Pursue run at `medium` only.

## Power

Power is the model dial: how much model each worker run gets. It never names
models. Per-connector tier tables translate the dial into a concrete model or
reasoning effort at selection time.

```bash
circuit run fix --goal "..." --power low
```

| Value | What workers get |
| --- | --- |
| `auto` | The run picks the tier. The researcher recommends one, the engine clamps it to your `power_auto` bounds, and the receipt reports the resolution: `power low (auto)`. |
| `low` | Research on the big tier, implementation on the small tier, review on the middle tier. |
| `medium` | The default. Research on the big tier, implementation and review on the middle tier. |
| `high` | Everything on the big tier. |

Research stays on the big tier at every dial position: the reading that
steers the run is the wrong place to save. A worker retry automatically runs
one tier up, capped at high. Explicit model or effort config always wins over
the dial.

To see what the dial resolves to before spending anything,
[`circuit preview <flow> --matrix`](/docs/cli/preview) prints the connector,
model, and effort each step would get at every dial position, without
spawning a worker.

Every flow supports the dial. Persist a default with `defaults.power` in
[config](/docs/configuration/config-file); the flag wins over config. Both
accept `auto`; the `power_auto` floor and ceiling bounds in config only apply
when the dial is `auto`. The end-of-run receipt line reports the dial position
and any escalations, so a cheap run that had to escalate is visible, not
silent.

## Tournament

Tournament fans out multiple candidates and selects one. Supported by Explore
and Prototype.

```bash
circuit run explore --goal "..." --tournament --tournament-n 3
```

| Flag | Description | Default |
| --- | --- | --- |
| `--tournament` | Fan out candidates and select one. | off |
| `--tournament-n <2\|3\|4>` | How many candidates to fan out. Requires `--tournament`. | `3` |

## Autonomous

Autonomous enables a bounded continuation loop that routes recovery flows when a
run does not complete. Supported by Build, Fix, Explore, Prototype, and Pursue.

```bash
circuit run fix --goal "..." --autonomous
```

## Compiled depth

A run records one compiled thoroughness value. Tournament and autonomous each
resolve to their own compiled depth; otherwise it is the depth dial. A flow
falls back to its defaults when you pass nothing.
