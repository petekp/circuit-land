A flow is a repeatable work pattern. You author it as a schematic, and Circuit
compiles it to the runtime graph a run follows.

## Stages and steps

A flow is organized into stages: Frame, Analyze, Plan, Act, Verify, Review, and
Close. Each stage holds steps, and each step is one use of a block.

<Mermaid
  label="Circuit's canonical stage order"
  chart={`
flowchart LR
  Frame --> Analyze --> Plan --> Act --> Verify --> Review --> Close
`}
/>

A step has a kind that decides what it does:

- **Relay**: delegate work to a worker through a connector.
- **Compose**: the orchestrator writes a report.
- **Verification**: run checks against the work.
- **Checkpoint**: pause for a decision.
- **Fanout**: run branches and join their outputs.
- **Sub-run**: run a child flow.

## Typed inputs and outputs

Every block declares a typed input and a typed output. Each one is a named,
versioned contract: `flow.brief@v1`, `plan.strategy@v1`, `change.evidence@v1`.
A step is one use of a block, so it carries that contract: it reads inputs of the
shapes it names and writes one typed output, a
[report](/docs/concepts/evidence-and-runs).

A step's output is itself a contract, so it becomes the input a later step reads.
Those contracts are how a flow wires together. A step is placed only where the
inputs it names are already produced upstream.

<Mermaid
  label="Each step's typed output is the next step's typed input"
  chart={`
flowchart LR
  Frame -->|flow.brief| Diagnose
  Diagnose -->|diagnosis.result| Plan
  Plan -->|plan.strategy| Act
  Act -->|change.evidence| Verify
  Verify -->|verification.result| Review
  Review -->|review.verdict| Close
`}
/>

So context is not skipped or lost between steps, and a step never hands forward a
result the next step cannot read. Each output is a known shape: you and the next
step read structure, not loose prose.

## Routes

Steps connect through routes: named outcome paths that decide what happens next.
A route either points to the next step or to a terminal target. The terminal
targets are `@complete`, `@stop`, `@handoff`, and `@escalate`, and each closes
the run with the matching outcome.

<Mermaid
  label="A step's route points to the next step or a terminal target"
  chart={`
flowchart LR
  S[Step] -->|route| N[Next step]
  S -->|route| C["@complete"]
  S -->|route| St["@stop"]
  S -->|route| H["@handoff"]
  S -->|route| E["@escalate"]
`}
/>

## The run folder

A run is one execution of a flow. It records a trace, the reports its steps
write, and the supporting evidence in its run folder, along with the state needed
to resume.
